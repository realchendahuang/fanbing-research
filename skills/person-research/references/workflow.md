# 工作流参考

## 初次研究

先记录对象姓名、公开身份锚点、问题与范围。建立少量优先入口，而不是搜集所有姓名命中。将原始发布、转载、采访和目录分开。

读取每个来源后记录标题、URL、日期依据、查看范围、定位、权利说明和不能证明的内容。为可引用主张分配稳定 ID；缺少证据的想法写成问题。

然后构建时间线、作品目录和有限综述。比较跨期重复做法时同步查找停止、相反意见与不适用情境。不会因为用户要求“蒸馏”就输出人格画像。

## 持续更新

增量单位是一项问题而不是一个人全部互联网足迹。新材料可能扩大、缩小或推翻旧解释；更新报告要把这些变化写清楚。

在标准仓库中使用根目录的 JSON 数据和脚本。作为独立 Skill 使用时，可以先输出有来源的 Markdown 草稿，再要求宿主/用户将其放入规范目录。Skill 自身不包含搜索 API、凭证、调度器或模型训练能力。

## 历史内容

顺着本人明确链接的旧站、文章标题与合法公共存档走。区分原文时间、迁移时间和抓取时间。当前域名内容不能自动代表历史所有者。

## 播客与视频

有音频或视频工具时，应核对合法可访问原材料、定位时间段和说话人，再写短引文或原创摘要。没有工具时只登记 shownotes。编辑文案、嘉宾发言和主持人表态必须分开。
